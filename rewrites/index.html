    Rewrite rules & thesis lineage¶

    This reference maps each algebraic rewrite to its compiler pass and shows how Parakeet 1.x builds on the two NYU PhD theses behind the original compiler:

    • [R] Alex Rubinsteyn, Runtime Compilation of Array-Oriented Python Programs (NYU, 2014) — type specialization, data-parallel operators, and fusion rules.
    • [H] Eric Hielscher, Locality Optimization for Data Parallel Programs (NYU, 2013; arXiv:1304.1835) — cache/register tiling and loop interchange over operator trees.

    (For the cohesive conceptual story behind these passes, read Operators & compilation walkthrough and Algebraic optimization first.)

    Where rewrites run¶

    1. During elaboration: array expressions stay delayed (index-to-value functions), so simple producer-consumer chains fuse on construction.
    2. In the middle end: 12 passes in parakeet.transforms.pipeline.PASSES rewrite the emitted operator IR (IndexMap, IndexReduce, IndexScan, IndexFilter, IndexExpand, IndexScatter, IndexWavefront) before loop lowering. Inspect what fired on any function with par.show_rewrite(fn, *args).summary().

    Fusion rules¶

    Producer-consumer (vertical) fusion ([R] Fig. 6.1)¶

    Chained operators separate passes
    Map(g, Map(f, X))  # np.tanh(x * a) + b
Reduce(g, +, Map(f, X))  # np.sum(x * x)
Scatter(+, idx, Map(f, X))  # np.bincount(idx, weights=w * s)
Map(g, Scan(f, +, X))  # np.cumsum(x) * 2 + 1
Reduce(g, +, Filter(p, X))  # np.sum(x[x > 0])
Filter(q, Filter(p, X))  # x[x > 0][x[x > 0] < 1]
    Fused operator 1 pass · 0 temporaries
    Map(g ∘ f, X)  # + affine inversion for transpose/slices
Reduce(g ∘ f, +, X)
IndexScatter(+, idx, f)
IndexScan(f, +, emit=g)  # fused into scan's emit block
FilterReduce(g, +, p, X)  # guarded loop, no index buffer
Filter(p ∧ q, X)  # single short-circuit compaction

    Safety guards added in 1.x (extending [R]):

    • Alias safety: every delayed array snapshots the store counter; a potentially aliasing store before consumption restarts elaboration with that array materialized eagerly.
    • Multi-use duplication guard: [R] had no cost guard; 1.x fuses an expensive delayed array at most once so repeated uses or loop bodies never recompute it.
    • Empty-mask semantics: FilterReduce requires single use of compacted indices and an explicit identity init (so np.min(x[mask]) still raises ValueError on an empty mask).

    Nested and sibling (horizontal) fusion ([R] Figs. 6.2–6.3)¶

    Separate or nested passes
    # Nested independent maps
[[f(x, y) for y in Y] for x in X]

# Sibling maps / reductions / scatters
a, b = np.sin(x), np.cos(x)
lo, hi = np.min(x), np.max(x)
gh = par.scatter_add(B, idx, g)
hh = par.scatter_add(B, idx, h)

# Two-pass logsumexp / softmax
m = np.max(x)
s = np.sum(np.exp(x - m))
    Merged operator
    # Single flattened N-D IndexMap (full parallelism)
IndexMap(f, shape=(len(X), len(Y)))

# Single traversal over x (or idx)
a, b = IndexMap2(sin, cos, x)
lo, hi = IndexReduce2(min, max, x)
gh, hh = IndexScatter2(B, idx, g, h)

# Single-pass online (m, s) carry fold
m, s = OnlineLogSumExp(x)

    On CUDA, independent contiguous elementwise maps of differing sizes (such as updating dozens of parameter tensors in an Adam step) also batch horizontally into one disjoint-union kernel to cut launch overhead.

    Tiling, locality, and shape specialization ([H] & [R] §6.4)¶

    Generalized IndexTile + TileStage

    Extends [H]'s TiledMap to any rank ≥ 2 IndexMap wrapping one IndexReduce (arbitrary folds, Carry states, and prologues/epilogues) — driving CPU L1/L2 cache tiles, 2×4 register jamming, GPU __shared__ / threadgroup staging, Metal simdgroup_matrix, and CUDA TF32 mma.sync from one IR.

    Target-aware reduction interchange

    Implements [H]'s PermuteReductions selectively via TargetProfile: on CPU, hoists strided associative inner reductions (np.sum(X, axis=0)) outside L1-sized output strips; skipped on GPU so warps stay coalesced across columns. Stencils are never tiled (matching [H]'s finding that tiling slows blur stencils).

    Associativity & linear algebra

    Reductions parallelize and vectorize only when the combiner is provably associative (+, *, min, max, and, or, &, |, ^); arbitrary user folds keep strict left-to-right order. a @ b lowers to Map(Reduce(+)) so prologues/epilogues fuse, while standalone CPU float a @ b dispatches to NumPy's cblas_?gemm unless config.blas = False.

    Value & shape-bucket specialization

    Extends [R] §6.4: size-1 broadcast dimensions are always static constants, compile-time arguments (axis, keepdims, tuple lengths) specialize automatically, and tiled/GPU passes propagate finite power-of-2 shape buckets and divisibility (DimInfo(lo, hi, align)) so aligned sizes (128, 256, 512, 1024, 4096) share one branchless fast-path binary.

    Scalar algebraic simplifications (x + 0, x * 1, x ** 2 → x * x, zero-copy view arithmetic, and redundant broadcast/bounds check elimination) happen on the fly during IR construction, delegating low-level CSE, LICM, unrolling, and SIMD codegen to clang/gcc/NVRTC/Metal.

    Operator differentiation rules¶

    par.grad attaches one reverse rule per algebraic operator (rather than differentiating flattened loops). See Automatic differentiation and Law 2: Algebraic rematerialization.

    Forward operator
    Map(f, X)  # elementwise
Reduce(+, X)  # sum reduction
Reduce(max, X)  # max reduction
Reduce(*, X)  # product reduction
Scan(+, X)  # prefix sum
A @ B  # matrix product
X[idx]  # gather
par.scatter_add(n, idx, v)  # scatter-add
np.sort(X)  # sort
    Reverse adjoint given output cotangent ȳ
    Map(∂f / ∂x * ȳ, X)  # summed over broadcast axes
broadcast(ȳ, X.shape)
ȳ * (X == result) / tie_count
zero_safe(ȳ * result / X)
ReverseScan(+, ȳ)
ȳ @ B.T, A.T @ ȳ
par.scatter_add(len(X), idx, ȳ)
ȳ[idx]  # gather
scatter(ȳ, inverse_permutation)

    Arbitrary non-elementary reductions use O(√N) checkpointed reverse replay, general par.map bodies differentiate per element with thread-privatized adjoints, and runtime if c: A else: B evaluates both pure branches and selects values and adjoints by c.

    Evolution from the 2013–2014 NYU theses¶

    Added in Parakeet 1.x new capabilities
    • Composable AD + Law 2 rematerialization: forward (jvp), reverse (grad/vjp), higher-order (hvp/hessian), and zero-tape attention/CCE adjoints.
    • Algebraic Laws 1–6: rescaled-monoid tiling (attention, CCE, RBF), contraction reassociation (MLA/GQA), chunkwise state-space scans (IIR, Mamba-2), TileInterval mask pruning, and ordered pairwise folds / fused histograms.
    • Soundness & specialization: alias and multi-use duplication guards on fusion, static size-1 broadcasts, DimInfo shape-bucket specialization, and checked runtime IndexError/ValueError exceptions.
    • Modern targets & surface: unified multi-core CPU, Apple Metal (simdgroup_matrix), and NVIDIA CUDA (TF32 mma.sync, NVRTC/PTX/nvcc, device residency), plus RaggedArray, wavefront DP, einsum, par.nn, and par.Alphabet/par.Vocab.
    In [R] / [H] only deliberately replaced or omitted
    • IR-to-IR loop AD: replaced by an operator-level algebraic tape during elaboration so adjoints undergo full fusion and tiling.
    • Recursive arbitrary-depth tiling & general TiledScan: 1.x focuses IndexTile on rank ≥ 2 map-of-reduce nests and TileScan on affine and bilinear recurrences.
    • Online runtime tile-size autotuning: replaced by analytical compile-time sizing from TargetProfile and config.tile_bytes.
    • Custom low-level scalar optimizer: delegated to clang/gcc, NVRTC, nvcc, and the Metal compiler.
