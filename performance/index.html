    Performance¶

    Looking for cross-library benchmarks?

    For head-to-head 1.0 comparisons against PyTorch, JAX, CuPy, Faiss, and PyKeOps on CPU and an NVIDIA A10, see Release benchmarks. This page explains when and why Parakeet wins or loses on CPUs and GPUs, how cache tiling behaves, and practical tuning tips.

    All numbers on this page were measured with python benchmarks/run.py on an Apple M1 Pro (10 cores, 32 GB), macOS 26.5, Python 3.12.6, NumPy 2.5.5; best of five runs, compilation excluded. "NumPy" is the same computation written with NumPy alone; "×" is the speed-up over it. Run the script on your own machine - results vary a lot between CPUs, compilers and array sizes.

    A big GPU on the work it is for¶

    python benchmarks/gpu_showcase.py on an NVIDIA A100 (Google Colab, 12 CPU threads, float32). The same Python source runs in every column.

    kernel size NumPy one core 12 threads A100 A100 vs 12 threads
    n-body forces 16,384 bodies – 1393 ms 238 ms 7.5 ms 32×
    k-means assignment 2M points × 256 centers × 16 2247 ms 9551 ms 1913 ms 75.8 ms 25×
    heat equation, 200 steps 2048² 7821 ms 4532 ms 370 ms 118 ms 3.1×
    Black-Scholes 20M options 625 ms 1746 ms 227 ms 111 ms 2.0×
    Julia set 4096² – 1425 ms 155 ms 95.5 ms 1.6×

    The first two are what a GPU is for: every element needs thousands of operations and the result is small. The n-body kernel is 186× faster than one core. The last three are bounded by moving their arrays across the bus once each way (Black-Scholes reads 240 MB and writes 80 MB); the heat equation is 600 loops over a grid that never leaves the device between them, which before arrays stayed on the device took 1.4 s here.

    A float matrix product is not in this table: on the CPU it goes to the BLAS (24 ms for 2048² on this machine), on the GPU it is Parakeet's own kernel (73 ms). Dense linear algebra on a GPU wants cuBLAS, which Parakeet does not call.

    100k × 64 760 ms 34.5 ms 27.3 ms 42.5 ms

    1024² – 82.2 ms 47.0 ms 6.4 ms
    2048² – 338 ms 197 ms 78.2 ms
    Harris corners 1024² 9.7 ms 2.9 ms 4.0 ms 3.0 ms
    4096² 292 ms 77.0 ms 88.8 ms 133 ms

    batch 4096 – 231 ms 189 ms 139 ms

    The GPU wins once each element costs real arithmetic (the Julia set from the smallest size, tanh from about 100k elements) and the result is not much bigger than the work that produced it. It ties or loses when a loop mostly moves memory, because every launch pays for the copy both ways: Harris at 4096² and all-pairs at 100k rows are slower on the device than on two CPU threads. Loops below config.device_threshold (32,768 iterations) never leave the CPU, which is why the decision tree, whose parallel loops run over 32 features, is a CPU program on every backend.

    The matrix product is the tiled one: on this machine it is within 2.5–3.5× of NumPy's OpenBLAS on one core.

    Reading the numbers¶

    Where Parakeet wins. Expressions with several operations (no temporaries, one pass over memory), code that needs a Python-level loop in NumPy (Julia set, GrowCut, pairwise kernels), and anything that can use all cores.

    Where it does not.

    • Dense linear algebra, when there is no BLAS to call. A product of two float matrices is handed to the BLAS NumPy itself uses, so it costs what it costs in NumPy. Parakeet's own tiled loops run everything else that has that shape (integer products, allpairs distances, products inside a parallel map or on a GPU) and are 3–10× behind a hand-tuned BLAS.
    • Single-threaded transcendental functions. NumPy ships SIMD implementations of tanh, sin, exp, ...; Parakeet's sequential backend calls the C math library one element at a time (the tanh row). With threads it is ahead again.
    • Memory-bound loops on a GPU. On this machine the 10 CPU cores usually beat the integrated GPU unless each element needs a lot of arithmetic (arc distance, convolution). Loops that mostly move memory (norm, stencils) lose, and repeatedly launching cheap kernels over a NumPy-owned array (diffusion) loses badly because the array is copied to and from the device on every launch.
    • Tiny inputs. A call into compiled code costs a few microseconds of argument marshalling; a NumPy call on a 10-element array is cheaper.

    Tiling¶

    A matmul-shaped operation is a map over pairs whose element is a reduction over data picked by each member of the pair: a matrix product, allpairs distances, a tropical product. Evaluated row by row, every row of the result sweeps over all of the second operand, which stops fitting in cache long before the arrays are large. Parakeet recognises the shape; any two-dimensional map whose element function is one reduction plus straight-line code, whoever wrote it; and does two things:

    • tiles the inner dimension, so a cache-sized block of the second operand is reused for every row before moving on (config.tile_bytes, by default half of a core's L2 cache);
    • jams the reductions of a 2×4 block of elements into one loop, so each loaded value is used several times.

    Neither changes what is computed, only the order. a @ b on 1024×1024 float64 (Apple M1 Max):

    one core all cores
    untiled 190 ms 43 ms
    tiled 92 ms 13 ms
    NumPy (Accelerate) 4.5 ms

    @jit(tiling=False) or config.tiling = False turns it off. The timings above are with config.blas = False; by default a float matrix product on a CPU backend calls the BLAS and takes the NumPy time.

    Tips¶

    • Prefer array expressions or comprehensions over index loops when they say the same thing: they parallelise, explicit for loops do not.
    • Keep work inside one @jit function so expressions can fuse across helper calls (helpers are inlined automatically).
    • @jit(bounds_check=False) removes index checks from explicit indexing in loops once the code is known to be correct.
    • Compiled code is specialised on whether an input is C-contiguous; contiguous arrays give the C compiler unit strides to vectorise.
    • parakeet.config.fast_math = True allows the C compiler to reorder floating-point arithmetic everywhere (results may change in the last digits).
