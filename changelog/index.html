    Changelog¶

    1.1.0 (November 25, 2026)¶

    Major expansion of Parakeet's GPU schedules, algebraic data structures, scientific/bioinformatics primitives, and documentation — unified under one top-level import parakeet as par (@par.jit, par.*) interface.

    Unified namespace, docs & benchmarks¶

    • Single unified parakeet namespace: Exported fold, topk, topk_fold, tanimoto_topk, ipa_attention, show_rewrite, RewriteReport, scatter, iscan, iscatter, and ifilter_reduce directly on top-level parakeet (with parakeet.dsl retained as a backward-compatible alias). Standardized examples and docs on import parakeet as par (@par.jit, par.*).
    • Reproducible benchmark figures & overhaul: Added tools/gen_benchmark_figures.py generating per-replicate scatter + IQR + median SVGs (bench-pairwise-l4.svg, bench-scaling-1nn.svg, bench-workloads-l4.svg) directly from docs/assets/colab-l4-0dcb7d5.json, reorganized the Benchmarks page by workload category, connected README.md directly to runnable implementations, and updated the NYU history links (Rubinsteyn 2014 thesis, Hielscher et al. 2013 arXiv:1304.1835, HotPar '12).
    • Bioinformatics & structural biology guide: Added the Bioinformatics & structural biology gallery (examples/bio_gallery.py) and reproducible benchmark suite (benchmarks/bio_workloads.py).

    GPU schedules & matrix units¶

    • Tiled GPU pairwise folds: Broadcasting NumPy and nested-map/structured par.fold exact 1-NN and inverse-distance smoothing now stream shared-memory score tiles (16 KiB/block) on CUDA and Metal with exact first-index tie and NaN semantics — 4.8× faster (2.60 ms → 0.54 ms) and 21× less global scratch (64 MiB → 3 MiB) at 1,024 × 16,384 × 32 on NVIDIA L4.
    • Hardware matrix units in monoidal kernels: Enabled Metal simdgroup_matrix and CUDA TF32 WMMA inside Law 1 rescaled-monoid kernels (FlashAttention, RBF, linear cross-entropy, nanoGPT training).
    • Device-resident GPU scans & reductions: Kept GPU prefix scans, small GPU reductions, and extrema values device-resident without host round-trips.

    New algebraic primitives & data structures¶

    • First-class RaggedArray (CSR) & segmented operators: RaggedArray, segment_ids, segmented_map, segmented_reduce, segmented_scan, segmented_softmax, and differentiable varlen_flash_attention with ragged reverse-mode AD (par.grad preserves offsets structurally).
    • 1-to-K ragged compaction (IndexExpand): Added par.flatmap and par.filter_pairs (two-pass count → prefix-sum → emit) with dead-output elimination and AD gather support.
    • Parallel sorting, search & lookup tables: Parallel radix sort / argsort / unique, fusible searchsorted, SortedIndex, and static open-addressed FrozenHashTable.
    • 3D spatial pruning & block-sparse attention (Law 5 generalized): morton_order, 3D AABB spatial_cutoff_sum, and CSR BlockMask block_sparse_attention with forward + backward AD.
    • 2D / banded semiring DP (IndexWavefront): Added par.wavefront, par.batched_wavefront, and Law 2 checkpointed differentiable par.soft_align (Smith-Waterman / Needleman-Wunsch / soft-DTW).
    • Vector-valued Carry folds & pair-biased / IPA attention: Multi-slot Carry folds powering exact par.topk, par.topk_fold, par.tanimoto_topk, and Law 1+2 par.ipa_attention.
    • Zero-copy bytes, bitops & Python ergonomics: Zero-copy uint8 bytes / mmap inputs, popcount/clz/ctz/rotl/rotr/bswap, bf16_to_f32 / f32_to_bf16, IntEnum, scalar match/case, frozen @dataclass dataclasses.replace, and structured NumPy views.

    1.0.0 (November 24, 2026)¶

    A ground-up rewrite for modern Python. The @jit decorator, the adverbs (map, reduce, scan, allpairs, imap, ...) and the overall idea are unchanged; everything underneath is new.

    Algebraic operators¶

    • The same CPU tile schedule serves exact nearest-neighbor queries written as broadcasting NumPy or nested parallel maps. It merges a distance and index per query and preserves the first index on ties.
    • Two weighted histograms over shared bin IDs can fuse into a single traversal. Structured folds accept tuples and named records with a user-defined merge.
    • Algebraic rewrites cover online normalized sums, their gradients, reassociation of contractions, and chunked affine scans. The rewrite inspector shows which passes fired for a given function and input.
    • The gallery includes runnable examples. The release benchmarks compare five workloads with general-purpose and specialist implementations on a four-vCPU worker and an NVIDIA A10.

    Highlights¶

    • grad and value_and_grad: reverse-mode differentiation as an adverb. Element-wise operators, reductions, matrix products, views, map and allpairs with your own functions all have derivative rules; loops of known length are unrolled; anything without a rule raises instead of returning a wrong gradient. examples/nanogpt.py and examples/convnet.py train with it.
    • More of grad: cumsum, sort, einsum, stacks of matrices, folds with any function, and if statements on run-time conditions (both branches run, results are selected). The derivative of a map runs in parallel.
    • A middle end: elaboration now produces operator statements (IndexMap, IndexReduce, IndexScan, IndexFilter, printed by spec.operators) and a pipeline of passes rewrites them before they become loops. Tiling is one such pass, a pattern match on the IR instead of a trial elaboration; vertical fusion (Map→Map including matmul epilogues, Scan→Map into emit, Map→Filter, Map→Reduce), filter fusion (Filter→Filter and Filter→Reduce: np.sum(x[x > 0]) is one loop and allocates nothing), sibling fusion (x.min(), x.max() and np.sin(x), np.cos(x) each share one loop), reduction interchange (np.sum(X, axis=0) becomes L1-tiled contiguous SIMD loops), and dead-operator elimination all run at this level; find_broken_transform bisects the pass list; config.skip_transforms switches passes off.
    • General operators: reduce, scan and filter take several arrays with map= (and emit=); np.einsum; @ on stacks; reductions over several axes in one pass; tiling for maps of any rank.
    • Parallel primitives: prefix scans (cumsum), filters (x[mask], nonzero) and argmin/argmax run in parallel, on CPUs and GPUs.
    • GPU: arrays stay on the device between the loops of one call; a loop is sent to the device by the work in it, not its element count.
    • BLAS: float matrix products call the BLAS NumPy uses.
    • Tiling: two-dimensional maps of reductions (@, allpairs distances, ...) run a cache-sized tile at a time with their reductions jammed 2×4. A 1024×1024 matrix product is 2× faster on one core and 3× on all of them.
    • np.sort and np.argsort take axis and sort every lane in parallel (N-d input used to be flattened without saying so).
    • The dimensions of an array argument can be compile-time constants when the code needs them to be (range(w.shape[0]) in a loop that must be unrolled).
    • parakeet.macro and parakeet.find_broken_transform are back, and the code is laid out in frontend/, syntax/, transforms/ and lib/ again.
    • Faster compiles for large functions: identical loop bodies are compiled once.
    • Checked on real NVIDIA hardware. The whole suite passes with every parallel loop forced onto a Tesla T4 (tools/colab_job.py, run on demand with runplz colab; not part of CI).
    • Reads like Parakeet again: two-space indentation, parakeet.prims and parakeet.ndtypes, and the 0.x helpers typed_repr, specialize, run_python_fn, openmp_available, rank/size/shape, plus the old config.opt_fusion / config.print_* option names.

    • Fixed: two arguments of one GPU kernel that view the same memory now share a device buffer (previously one of them could read a truncated copy).

    • Python 3.11+ and NumPy 2, no dependencies besides NumPy and a C compiler (the dsltools, appdirs, llvmpy and PyCUDA dependencies are gone).

    • New frontend. Functions are elaborated directly into a typed loop IR: calls are inlined, closures/tuples/slices are resolved at compile time, and array expressions are fused into their consumers.
    • Backends: sequential C; multi-core through a built-in thread pool, OpenMP or Grand Central Dispatch; Apple GPUs through Metal; NVIDIA GPUs through CUDA (CuPy/NVRTC, no nvcc needed). GPU backends fall back to the CPU per loop, with a warning that says why.
    • NumPy-exact typing (NEP 50): result dtypes match NumPy, including the treatment of Python scalars.
    • Safety: bounds checks, shape checks, division and domain checks raise the same exceptions NumPy/Python would; compile errors carry the source location and the chain of inlined calls; reference-counted temporaries are freed eagerly (no more leaks in loops).
    • Much larger language subset: early return, break/continue, while, keyword/default/*args arguments, walrus, assert/raise, boolean-mask and integer-array indexing (reads and writes), in-place operators with NumPy aliasing semantics, 0-d and empty arrays, all integer/float dtypes.
    • Much larger library: ~200 NumPy functions and methods, np.random (a counter-based generator that is reproducible in parallel and on GPUs), sorting, math, and most numeric builtins.
    • Globals and closure variables are read at call time (no stale constants); arguments that must be compile-time constants (such as axis) are specialised on demand.
    • Compiled modules are cached on disk and shared between processes.
    • parakeet.config, parakeet.options(...), PARAKEET_* environment variables, f.specialize(...).ir/.source/.kernels, available_backends().

    Removed¶

    • Python 2 support, the LLVM backend, the interp backend (use backend="python"), typed_macro/staged_macro, and most of the old config.opt_* flags.

    Releases before the rewrite¶

    0.24 / March 24th, 2014¶

    • cache compiled code by hash of generated C source
    • tuple slicing
    • fixed (or disabled) unreliable optimizations
    • casting between array types using map over elements

    0.23 / November 21st, 2013¶

    • Generalized StrideSpecialization to ValueSpecialization
    • Significantly decreased overhead of calling into Parakeet (though still ~500x slower than a normal Python call)

    0.22 / November 20th, 2013¶

    • Changed NumPy calls to use newer API, cuts down on number of compile warnings
    • If compilation fails, retry using distutils, may help some people on Windows

    0.21 / November 19th, 2013¶

    • Got rid of testing dependency on SciPy
    • Deleted unused and unfinished optimizations
    • Small misc. bugs

    0.20 / November 19th, 2013¶

    The last release added experimental CUDA support but the performance was terrible. This release includes lots of tweaks and optimizations necessary for getting beneficial speedups on the GPU. However, the default backend remains OpenMP since some program constructs will not work on the GPU and the nvcc compile times are unacceptably slow.

    • Expanded and generalized fusion optimization
    • Filled in missing methods from shape inference
    • Using ShapeElimination on every function (repurposes the shape inference results as a symbolic execution optimization)
    • Fixed lots of small bugs in other optimizations exposed by ShapeElimination
    • Shaved off small amount of compile time by moving away from Node pseudo-ASTs to regular Python constructors
    • Hackishly added int24 just as a sentinel for default values in reductions that need to cast up to int32 from bool, int8, int16.
    • Eliminate redundant & constant array operator arguments with SpecializeFnArgs

    0.19 / November 4th, 2013¶

    • Added experimental CUDA backend (use by passing _backend='cuda' to functions wrapped by @jit)

    0.18 / October 30th, 2013¶

    • Added OpenMP backend (runs most map-like computations across multiple threads)
    • Stack-allocate representations for all structured types in C
    • Disabled Flattening -- tricky transform needs careful audit
    • Debugged and enabled CopyElimination
    • Fixed negative step in slices
    • Added RLock around AST translation to play nice with Python threads (thanks Russell Power)
    • Fixed link argument order for building on cygwin in Windows (thanks Yves-Rémi Van Eycke)

    0.17 / October 9th, 2013¶

    • Added support for binding multiple variables in a for loop (i.e. "for (x,(y,z)) in enumerate(zip(ys,zs)):")
    • More array constructors support 'dtype' argument
    • macros can now generate wrapper functions with keyword arguments
    • lib_helpers._get_type can pull element types out of a wider range of values
    • Added more unit tests from Python benchmarks
    • Added option to manually specify compiler in c_backend.config.compiler_path
    • Slightly better support for negative indexing but negative step sizes are still mostly broken

    0.16.2 / October 1st, 2013¶

    • Moved version info into submodule so setup.py can run without full dependencies (thanks rjpower).
    • Fixed support for references to global arrays.
    • Make C backend respect runtime changes to config flags.
    • Got rid of unncessary linking against libpython.

    0.16.1 / September 30th, 2013¶

    • Fixed bugs in C backend and a several optimizatons.
    • Only print stderr if C backend fails to compile.

    0.16 / September 27th, 2013¶

    • Added flattening transformation which gets rid of all structures except scalars and pointers.
    • Created new C backend which compiles with either gcc or clang.
    • Disabled some of the more powerful optimizations (i.e. scalar replacement) which might introduce bugs.
    • Revamped the optimization pipeline to avoid running duplicate transformations and allow for better logging.
    • "Indexify" all adverbs by turning them into ParFor/IndexReduce/IndexScan.
