    The compiled language¶

    Parakeet compiles a subset of Python chosen so that every value has a type known at compile time. This page describes that subset and the places where compiled code deliberately differs from running the same function in CPython.

    Values and types¶

    Python value Inside compiled code
    int, float, bool 64-bit integer / double / bool, weakly typed like NumPy treats Python scalars
    NumPy scalars (np.float32(1), np.complex64(1+2j), ...) scalars of exactly that dtype (complex lowers to unboxed (re, im) float pairs)
    NumPy arrays bool, int8–int64, uint8–uint64, float32, float64, complex64, complex128; any number of dimensions, any strides
    tuples (also nested) compile-time structures of the above
    NamedTuples and @dataclass objects (frozen or non-frozen) fields hold scalar, array, or nested record leaves; supports pure methods, @property, __call__, and local functional field rebinding (obj.x = v)
    dictionaries with fixed string keys key order is part of the structure, with lookup by literal key
    lists, list comprehensions homogeneous numeric literals build arrays; [] and mutated/heterogeneous lists compile as zero-overhead compile-time lists (.append, .extend, .pop, .clear), automatically promoting to a growable CPU buffer when mutated inside a dynamic loop or runtime branch; use par.fixed_list(cap, dtype) for zero-malloc thread-local scratch inside parallel loops and GPU kernels
    None, strings, dtypes, functions, modules compile-time constants
    slice, range, zip, enumerate, itertools (pairwise, islice, chain, product, batched) supported as values and in zero-allocation for loops / generator expressions

    float16 data is widened to float32. complex64 and complex128 lower to unboxed (re, im) float views across CPU, multicore, Apple Metal (complex64), and CUDA, and compose with Wirtinger par.grad and par.jvp. Object arrays, general-purpose mutable containers, sets and arbitrary non-dataclass class instances are not supported; passing one raises a TypeError naming the type.

    Type promotion follows NumPy 2 (NEP 50) exactly: float32_array * 2.0 stays float32, int8_array + 1 stays int8, int32_array / 2 is float64.

    Statements¶

    Supported: assignment (including tuple unpacking, augmented and annotated assignment, :=), if/elif/else, for over ranges, arrays, tuples, zip and enumerate, optional else on for and while, break, continue, return anywhere, nested def and lambda, assert, raise of built-in exceptions with a literal message, pass, del.

    Not supported: try/except, with, classes, generators (yield), global /nonlocal, import inside a compiled function, f-strings and print. Each of these produces an UnsupportedError at the offending line.

    Loop else runs on normal exhaustion, including an empty input. A break skips the corresponding else suite. Strict zip checks lengths at exhaustion. Chained scalar comparisons evaluate each reached operand once and short-circuit.

    Unfiltered multi-for comprehensions over independent ranges or arrays compile as Cartesian maps. The rightmost iterator varies fastest. A scalar consumer such as sum(x * y for x in xs for y in ys) can fuse the map into its reduction. Inner iterators with observable setup and dependent domains such as for j in range(i) are outside this subset.

    Functions¶

    • Any Python function called from compiled code is inlined: helpers do not need @jit. Recursion is therefore not possible and is reported as an error.
    • Positional, keyword, default, keyword-only, *args, and **kwargs arguments (as well as **d unpacking from compile-time dicts, functools.partial, and operator.* callables) all work cleanly.
    • Functions are first-class at compile time: pass them as arguments, store them in variables, close over local variables.
    • Globals and closure variables are read on every call, like in Python. If a global changes type, a new specialization is compiled.

    Arrays¶

    Compiled code follows NumPy semantics for views and mutation:

    @jit
def f(x):
  v = x[1:]  # a view of the caller's array
  v[0] = 0  # ... so this modifies x
  x += 1  # in place, visible to the caller
  y = x * 2  # a new array
  x[1:] = x[:-1]  # overlapping assignment behaves as if a temporary were made
  return y
    • Basic indexing (x[i, 1:-1, ::2, None, ...]), integer-array indexing and boolean masks work for reading and writing.
    • Indices are bounds-checked (IndexError); shapes are checked when broadcasting (ValueError). Use @jit(bounds_check=False) to drop index checks.
    • Returning an input returns the same object; returning a view of an input returns a NumPy view of the caller's memory.
    • Read-only arrays may be read; writing to one raises ValueError.

    Differences from CPython / NumPy¶

    One static type per variable : A variable assigned an int on one path and a float on another is a float everywhere (the usual numeric promotion). A function returning 1 in one branch and 2.5 in another returns a float from both. Types that cannot be unified (say an array and None) are an error if the variable is used afterwards.

    Rank is static : The number of dimensions of every array is fixed at compile time. Functions whose result rank depends on values (for example np.squeeze(x) when it cannot be known which dimensions have length 1) ask you to pass axis=.

    Compile-time constants : Some arguments must be known at compile time: axis, keepdims, the length of a shape tuple, a dtype. If such a value comes straight from an argument of the compiled function, Parakeet specialises on its value automatically; otherwise it reports which expression must be constant.

    Lists and dynamic loops : Numeric literals like [1.0, 2.0, 3.0] and [f(x) for x in xs] still build arrays directly. Local lists built with outs = []; outs.append(...) stay completely unboxed at compile time in straight-line and unrolled code (so np.stack(outs) and RaggedArray.from_sequences(outs) work with zero heap allocation and compose with par.grad), and automatically promote to a growable homogeneous CPU buffer with geometric doubling when appended inside a runtime for/while loop or dynamic if branch. Inside parallel par.parfor/par.map bodies and GPU kernels (CUDA/Metal), par.fixed_list(cap, dtype) provides a fixed-capacity stack-allocated scratch buffer with zero malloc. Variables holding arrays or RaggedArrays may also be rebound to different shapes across while/for loop iterations (for example, shrinking an active frontier with arr = arr[mask]).

    Integer arithmetic : Python ints are 64-bit and wrap on overflow (like NumPy), they are not arbitrary precision.

    float16 : Operations NumPy would compute in half precision are computed in float32.

    Loop variables after a loop : A variable first assigned inside a loop body keeps its last value after the loop, but if the loop never ran it is zero (CPython raises NameError).

    Random numbers : np.random functions use Parakeet's own generator (see parakeet.seed); the streams differ from NumPy's.

    Parallel side effects : parakeet.map, comprehensions and array expressions may evaluate their elements in parallel and in any order. Reductions with a user-defined function assume it is associative only when Parakeet can prove it (for +, *, min, max, &, |, ^); otherwise they run sequentially.

    Fixed records at the call boundary¶

    Named tuples preserve their field names and result type. @dataclass objects (frozen or non-frozen) and dictionaries with fixed string keys can contain arrays, scalars, discrete metadata, or nested records. Pure methods, @property, @staticmethod, @classmethod, and __call__ on dataclasses and named tuples are inlined directly at elaboration time with zero PyObject overhead, and local field assignments (obj.x = v, obj.x += v) on non-frozen dataclasses functionally rebind the compile-time record (value semantics, zero heap mutation). Fields and keys are part of the specialization, while array data and scalar fields remain ordinary runtime arguments. Returning these containers reconstructs their structure and keeps the usual array view semantics.
