    API reference¶

    Compiling¶

    parakeet.jit ¶

    Compile a numerical Python function to native code on first call.

    Use it bare (@jit) or with options (@jit(backend="metal")). The function is specialised for each distinct combination of argument types; every later call with the same types runs the cached native code.

    Options (all default to the corresponding parakeet.config setting):

    backend "auto", "c", "multicore", "threads", "openmp", "gcd", "metal"/"mps", "cuda" or "python". bounds_check Raise IndexError for out-of-range indices instead of crashing. fusion Fuse array expressions into single loops. tiling Tile matmul-shaped loops for cache locality.

    specializations property ¶

    specialize(*args, **kwargs) ¶

    Compile (without running) for the given example arguments.

    inspect(*args, **kwargs) ¶

    Print the typed IR generated for the given example arguments.

    parakeet.run(fn, *args, **kwargs) ¶

    Compile fn (if needed) and call it: parakeet.run(f, x, y).

    parakeet.Specialization ¶

    One compiled version of a function for specific argument types.

    ir property ¶

    The typed loop IR of this specialization (after every pass), as text.

    source property ¶

    The generated C source.

    kernels property ¶

    Source of every device kernel (empty for CPU backends).

    signature property ¶

    Backends and settings¶

    parakeet.available_backends() ¶

    Which backends work on this machine, with a reason for those that do not.

    parakeet.options(**settings) ¶

    Temporarily override configuration settings.

    with parakeet.options(backend="c", bounds_check=False): ... result = f(x)

    parakeet.seed(value=None) ¶

    Seed the random number generator used by np.random in compiled code.

    Compiled code has its own counter-based generator (it must be usable from many threads and on GPUs), so streams differ from NumPy's, but are reproducible for a given seed and sequence of calls.

    parakeet.clear_cache() ¶

    Remove all compiled modules from the on-disk cache.

    Exceptions¶

    parakeet.errors ¶

    Exception hierarchy.

    Compile-time problems are reported as :class:CompileError subclasses that carry the location of the offending Python source, so the message points at the user's code rather than at Parakeet internals. Runtime problems detected by generated code (out-of-bounds indices, shape mismatches, ...) are re-raised as the same built-in exception NumPy/Python would have raised.

    ParakeetError ¶

    Bases: Exception

    Base class of every error raised by Parakeet itself.

    CompileError ¶

    Bases: ParakeetError

    The function could not be compiled.

    location is the innermost source position; call_chain lists the call sites (outermost first) through which the failing code was inlined.

    UnsupportedError ¶

    Bases: CompileError

    A Python/NumPy feature outside the subset Parakeet compiles.

    TypeInferenceError ¶

    Bases: CompileError, TypeError

    Types could not be reconciled (also catchable as TypeError).

    StaticValueError ¶

    Bases: CompileError, ValueError

    A value that must be known at compile time was not, or was invalid.

    BackendError ¶

    Bases: ParakeetError

    A backend failed to build or run generated code.

    BackendUnavailable ¶

    Bases: BackendError

    The requested backend cannot run on this machine.

    The message always says what is missing and how to get it.

    CCompilerError ¶

    Bases: BackendError

    The system C compiler rejected generated code (a Parakeet bug).

    InternalError ¶

    Bases: ParakeetError

    An invariant inside Parakeet was violated - please report it.

    FallbackWarning ¶

    Bases: UserWarning

    A parallel loop could not run on the requested device and ran on the CPU.

    SourceLocation dataclass ¶

    A position in the Python source of a function being compiled.

    frame() ¶

    A small code frame: file:line plus the source line and a caret.

    Algebraic DSL & rewrite inspection¶

    parakeet.dsl.show_rewrite(fn, *args, backend=None, blas=False, **opts) ¶

    Compile-only algebraic rewrite inspection for fn on the types of args.

    Works reliably on cold or warm specializations (including repeated calls and calls after ordinary execution), supports plain functions, @jit / @dsl.kernel functions, and grad / value_and_grad wrappers without executing fn or mutating global compiler state.

    parakeet.dsl.RewriteReport dataclass ¶

    Side-by-side summary of an algebraic rewrite performed by Parakeet.

    Testing helpers¶

    parakeet.testing ¶

    Helpers for testing compiled functions against NumPy / pure Python.

    check(fn, *args, backends=None, rtol=1e-06, **kwargs) ¶

    Run fn in Python and compiled on every backend; results (including their types) and any in-place changes to array arguments must agree.

    same(actual, expected, rtol=1e-06) ¶

    Strict comparison: values, shapes and types (Python vs NumPy scalar, dtype). Returns a description of the first difference, or None.

    expect(fn, args, expected, msg=None, valid_types=None, backends=None) ¶

    Assert that fn(*args) compiled by Parakeet equals expected on every available CPU backend.

    eq(x, y, rtol=1e-05, atol=1e-08) ¶

    Structural, tolerance-based equality for scalars, arrays and tuples.
